# 学習実績の自動収集

学習アプリ（GitHub Pages）→ Apps Script → 指定スプレッドシートの「学習実績」タブ。
教材は従来どおりビルド不要・オフライン対応です。実績送信だけにGoogle側の処理を追加しています。

## 設置手順（シート所有者・編集者）

1. [指定スプレッドシート](https://docs.google.com/spreadsheets/d/1-IrnMRAI7-Czu4LR5iAWc-AaGn76Q5vx74SbdqmYw6A/edit)を編集できるアカウントで開く。
2. 「拡張機能 → Apps Script」を開く。既存スクリプトがある場合は置き換えず、別のApps Scriptプロジェクトを作成する。
3. このフォルダの `Code.gs` を貼り付けて保存する。指定シートIDは設定済み。
4. `setup` を一度実行し、Googleの権限確認を完了する。「学習実績」タブと見出しが作成される。他のタブは変更しない。同名タブの見出しが異なる場合はエラーで停止する。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」を選び、実行するユーザーを「自分」、アクセスできるユーザーを「全員」にしてデプロイする。スプレッドシート自体の公開設定は変更不要。
6. 送信先を変更する場合は `js/reporting.js` の `REPORT_ENDPOINT` を修正します。発行された `https://script.google.com/macros/s/…/exec` をコピーする。編集者向けの `/dev` は使わない。
7. 教材ホームの「学習実績の自動送信」を開き、学習者コード（例：S001）を入力し、自動送信をONにして保存する。端末・ブラウザごとに一度設定する。
8. 下の受信確認を行う。スクリプト更新時は既存デプロイを編集し、新しいバージョンに切り替える。

学校のGoogle Workspaceで匿名公開が禁止されている場合、この方式はそのまま利用できません。管理者の設定に合わせた認証方式が必要です。

## 集計の意味

- 通常ステージ・復習：最後の回答を採点した直後に1件送信。結果ボタンを押す前にも送信されます。
- ボス戦：勝利または敗北時に1件送信。
- LEAP：3分経過または全件完了で、判定が1件以上ある場合に送信。手動中断は対象外。
- 共有された1問の練習は対象外。途中の問題から開始して最後まで解いた場合は「途中からの練習」がTRUE。
- 回答数はその回の延べ回答数。正答率は正解数÷回答数×100の整数。模擬試験の配点による得点とは別です。
- LEAPは自己判定のため正解数・正答率・得点を空欄にし、判定数と「覚えた語数」を記録します。
- 完了日時は端末時計、受信日時はGoogle側の時計です。シートのタイムゾーンを運用地域（日本ならAsia/Tokyo）に設定してください。
- 学習時間は既存計測があるLEAPのみ。通常学習の時間を推測して記録しません。
- 教科横断の復習は1件にまとめ、教科欄を「教科横断」とします。

## 送信と再送

送信先は `js/reporting.js` の `REPORT_ENDPOINT` に固定しています。変更はソースの定数を修正してください。以前端末に保存したURLは使わず、送信待ちの実績も現在の固定URLへ送ります。完了時の学習者コード・実績IDは再送時も維持します。実績は1件1キーで保存するため、別タブの新しい実績で上書きしません。

アプリ起動・通信復帰・画面への復帰・表示中の1分間隔・手動の再送で送信を試みます。アプリを閉じたままでのバックグラウンド送信は行いません。OFFは新規収集と再送を止めます（すでに通信中の1件は取り消しません）。ブラウザのサイトデータを消すと送信待ちも消えます。

受信側はロック中に実績IDを検索して重複を排除します。書き込み後の応答が失われても同じIDの再送は行を増やしません。シートの実績ID列や既存行を削除すると重複判定できなくなるため、集計用の加工は別タブで行ってください。

ブラウザは保存成功と実績IDが一致した応答を確認して初めて「記録済み」にします。通信失敗・Googleのログイン画面・CORSによる応答読み取り失敗は送信待ちのままにします。`no-cors`の応答を成功として扱う処理はありません。

## 公開後の受信確認

1. 学習者コードをTEST001にして1ステージを完了し、結果画面の「記録済み」とシートの1行を確認。
2. 結果画面を再読み込みしても行が増えないことを確認。
3. オフラインで別ステージを完了し「送信待ち」を確認。オンラインへ戻して1行だけ増えることを確認。
4. 同じ単元をもう一度解いたときは別IDで1行増えることを確認。
5. 復習・ボス勝敗・LEAP完了を確認。LEAPの正答率が空欄で、手動中断は記録されないことを確認。
6. GitHub Pages本番と使用するスマホでも実施する。Google側の公開設定・権限・ブラウザによって応答を読めない場合は運用開始せず設定を確認する。

## 運用上の範囲

学習者コードは自己申告で、本人認証や改ざん防止にはなりません。公開エンドポイントへ実績を送れる設計なので、成績評価の証明用途には使わず、学習状況の把握に使います。秘密鍵やGoogle認証トークンを教材のソースへ埋め込まないでください。氏名・メール・解答内容・全セーブデータは送信しません。

大量運用ではApps Scriptの実行制限と、ID列検索の処理時間を確認してください。自動送信が止まっても教材は学習を継続できます。

## 検証状況

自動テストは送信待ち保持、成功応答確認、再送、重複排除、セッション復元、LEAP区分を検証します。Googleへの設置・公開・実受信は別途必要です。この作業時点では連携アカウントから指定シートへのアクセスが403のため、Google側は未変更です。

公式仕様：[Apps Scriptウェブアプリ](https://developers.google.com/apps-script/guides/web)、[Content Service](https://developers.google.com/apps-script/guides/content)。
